# TAB format

`.tab` is the input format of Wayne Cripps's `tab` program. Oud reads and
writes that format and adds no syntax of its own (maintainer decision,
2026-09-29). Content the format cannot hold goes to a sidecar file with a
warning (`TODO.md` `C15`).

`.tab` has first-class support but is not Oud's main format: it cannot hold
several voices or staffs, lyrics beyond chord text, or tuplet timing, which
MusicXML and FT3 carry (maintainer direction, 2026-09-29).

## Reference

- Manual: `README` in <https://github.com/mandovinnie/Lute-Tab> (the Dartmouth
  pages are gone). Version checked: `tab` 4.3.108.
- The program's license forbids commercial use and requires its notice on
  copies. Do not vendor its source, fonts, or sample files here. Write fixtures
  by hand.
- Reference parser: build the program (`make`, g++ only) and run
  `TABFONTS=<checkout> ./tab -v file.tab -o out.ps`. Each `pass1: ... l:` line
  in the output is one parsed chord: flag, second character, then positions
  1–9. `./tab -ascii file.tab -o out` writes a text rendering. Integration tests
  that use the program must be marked and skip when it is absent.

## Line structure

A chord line starts with a flag or line type (`0`–`5`, `W`, `w`, `B`, `L`, `x`,
`#`, `t`, `R`, `b`, `S`, …). An optional modifier may follow it: `.` dot, `#` grid, `*`
dot in grid, `|` extra flag bar, `!` no flag, `-` place marker, `Q`/`@`
highlight, `B` dot before, `&x` flag ornament. Any other character is already
course 1. `#`, `t` (triplet) and `R` (rest) lines carry the flag as their second
character: `#2d`, `t3a`, `R2`. Then come nine note positions, one character each:

| Position | Meaning |
|---|---|
| 1–6 | Courses 1–6, top line first |
| 7 | Bass courses 7 and up, below the staff |
| 8–9 | Courses 8 and 9 written without slashes, and marks below the staff |

A space means no note. Prefix symbols belong to the note that follows them and
take no position: `+`, `+*`, `x`, `#`, `$`, `*`, `%`, `,`, `'`, `=`, `^`, `@`,
`_`, `` ` ``, `Q`, `<`, `<!name>`, `"c` (any character as prefix), `\1`–`\4`,
`\.`, `\:`, and slashes before a letter. Postfix `&c` follows a note and takes
no position either. Marks that do take a position: `[`, `]`, `(`, `)`, `{`, `}`,
`U`, `X`, `|`, `.`, `:`, `/` before a space, `\\`, and `-` (a vertical
"play simultaneously" bar, not padding). `R` among the positions makes the
chord a rest; `M` or a tab starts the music line and `T` the chord text.

Bass courses share position 7: `a` = course 7, `/a` = 8, `//a` = 9, `///a` = 10
(the program also writes `//` as `s` and `///` as `t`); `4`, `5`, `6` = open
courses 11, 12, 13 (`score.cc` reads them as tuning entries 11–13).

Frets: `a`–`i` = 0–8, `j` = 9, `k` = 9, `l` = 10, up to `p` = 14. The
program's pitch code gives `j` 9 and its MIDI code gives it 8; Oud follows the
pitch code. Upper-case `D`–`I` are glyph variants of the same frets.

Italian digits: `0`–`9`, `!x` = 10 (bare `x` is an ornament), `y` = 11, `z` = 0,
`Nxx` = fret xx. Digits count from the lowest course: position 1 is course 6,
unless the file sets `-milan`. A file is Italian when it sets `-i`, `-O`, `-x`,
`-milan` or `$numstyle=italian`, or its chord lines hold digits and no letters.

`-tuning` lists courses from the lowest to course 1 (the program reads it right
to left). Octave digits count downward: an octave starts at `a`, and `4` is the
lowest octave. A 10-course Renaissance lute in G is
`-tuning C4D4E4F4G4c3f3a2d2g2`. `+` = sharp and `-` = flat. Oud stores tuning
in scientific pitch and converts on read. Program notation never has rising
octave digits from bass to course 1 and scientific pitch never has falling ones,
so a tuning already in scientific pitch is kept as written.

## Oud's earlier dialect

Files that start with `% Generated by oud` were written by Oud before it
followed the program. They are read by their own rules: each character after the
flag (and an optional `!`, `.`, `#`) is one course, `-` pads empty courses, bare
`x` is Italian fret 10, `q`–`t` are frets 15–18, and `-tuning` is scientific
pitch. Oud reads such files as before and writes the program's syntax when it
saves them.

## What Oud writes

- A first line `% Written by oud`, then `$numstyle=italian` for Italian
  tablature, `-tuning` in the program's notation, titles in `{…}`, a blank line.
- Each system opens with `b`, every bar ends with `b`, and a blank line ends a
  system. Systems follow the piece's system breaks; a piece without any gets a
  break every 4 bars, because the program never wraps lines by itself.
- An `S` line on the first bar, where the meter changes, and on an empty bar
  (which needs a line to survive reading). C is `SC`, cut C `Sc`, one-digit
  meters `S34`, others `S12-8`.
- Chord lines: the flag, `.` when dotted, then positions with spaces for empty
  courses and `-` as place marker when the first position would read as a
  modifier. Rests are `R` lines. Frets past `p` (14) are `Nxx`; Italian uses
  digits, `!x`, and `Nxx`, lowest course first. Bass courses go to position 7
  (`a`, `/a`, `//a`, `///a`, digits 4–6 for open courses 11–13), with courses
  8 and 9 also allowed in positions 8 and 9.
- What the format has no line for goes into comments the program ignores:
  `% tempo: N`, and `% tuning: …` when the tuning has no exact `-tuning`
  spelling (below A1, within one octave, or not listed bass first).
- A chord the format cannot hold (fret above 30, a second bass course beyond
  positions 8–9, a course above 13) stops the save with an error naming it.
  `C15` replaces that with a MusicXML sidecar.
- `tests/test_tab_export_original.py` covers these rules and an integration
  test reads Oud's output with the program when `TAB_PROGRAM` names a build.

## Support in Oud

Status after a load → save → load round trip, checked 2026-09-29 against the
manual and the reference parser; `tests/test_tab_import_original.py` holds the
reading cases. **Preserved** means Oud does not model the construct but writes
it back verbatim (`tests/test_tab_preservation.py`): an unedited file in the
program's syntax saves byte-identically after Oud's first header line. A chord
line is reused while it still reads as the chord; an edited chord is written
fresh and loses its marks. The header is reused while its title, composer,
author, tuning and tempo are unchanged; otherwise Oud writes a fresh header and
keeps the other header lines. Files in Oud's earlier dialect are rewritten. **Lost** means the construct is read but
dropped silently, which violates the `C15` rule.

| Dotted flag `2.` | Supported | |
| Breve `B`, longa `L` | Preserved | Read as whole notes; the line is written back while unedited |
| Grids `#2`, `x` | Preserved | Durations are modelled; the grid is kept by writing the line back while unedited |
| Triplet `t3` | Partial | Written back while unedited; tuplet timing is not modelled and a warning says so |
| Rests `R2`, `R1.` | Supported | |
